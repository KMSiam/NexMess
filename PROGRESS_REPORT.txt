  Auth (email + Google OAuth), Admin/Manager controls.

SESSION 2026-05-09 (evening) — COMMITTED
================================================================================

Commit: fix: password reset redirect race condition

Bug: After clicking "Update Password" in the password reset flow, the app
showed "Redirecting..." but landed on /login instead of /dashboard.

Root causes and fixes:

  1. App.tsx — Route placement bug
     /update-password was inside <AuthGuard>, which redirects to /login if
     session is null. Users arriving via the reset email link have only a
     recovery token (not a full session yet), so AuthGuard blocked them.
     FIX: Moved /update-password to a standalone route outside both guards.

  2. UpdatePasswordPage.tsx — Navigate called before session settles
     navigate('/dashboard') was called immediately after updateUser() resolved,
     but Supabase fires USER_UPDATED (and sometimes SIGNED_OUT as the recovery
     token is consumed) asynchronously afterwards. AuthGuard at /dashboard then
     saw session = null and redirected to /login.
     FIX: Removed direct navigate() from handleUpdate. Navigation now happens
     inside onAuthStateChange when USER_UPDATED fires with an active session.
     Spinner stays active until that event arrives.

  3. authStore.ts — Over-broad session clearing
     Condition `event === 'SIGNED_OUT' || !session` cleared all auth state if
     ANY event fired with a null session, including mid-flow recovery events.
     FIX: Split into separate guards — SIGNED_OUT clears state; other events
     with no session silently return without wiping anything.
